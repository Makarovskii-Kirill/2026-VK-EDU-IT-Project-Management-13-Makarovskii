# Практическое задание №6


### Риск 1. Срыв сроков MVP

**Тип:** внутренний

**Описание:** NLP-модель на старте дает низкую точность на реальных документах заказчика. Потеря времени на дообучении и разметке данных вместо разработки функционала.

**Уровень:** критический (вероятность высокая, влияние высокое)

**Стратегия — снижение:** MVP запускается с ограниченным числом классов документов (3 типа: счет, договор, акт). С остальным помогает оператор. 20% буфер в сроках.

---

### Риск 2. Низкая точность NLP на плохих сканах

**Тип:** внутренний
**Описание:** контрагенты присылают сканы низкого качества (фото телефона, мятые, размытые). Ошибка модели, снижение доверия к системе.
**Уровень:** высокий (вероятность высокая, влияние среднее)
**Стратегия — снижение:** внедряем индикатор уверенности (зеленый/желтый/красный). Поля с низкой уверенностью сразу отдаем на ручной ввод. Собираем базу плохих сканов для дообучения.

---

### Риск 3. Отказ пилотного заказчика

**Тип:** внешний
**Описание:** пилот — единственный источник фидбека и кейса для продаж. Сопротивление сотрудников или неготовность инфраструктуры.
**Уровень:** высокий (вероятность средняя, влияние высокое)
**Стратегия — снижение:** запускаем 2 пилота параллельно. Перед стартом фиксируем критерии успеха в договоре. Выделяем персонального инженера по внедрению.

---

### Риск 4. Утечка данных из закрытого контура

**Тип:** внутренний
**Описание:** система обрабатывает финансовые и юридические документы внутри контура заказчика. Уязвимость в Docker-образе или ошибка в конфигурации.
**Уровень:** высокий (вероятность низкая, влияние высокое)
**Стратегия — снижение:** шифрование чувствительных данных, регулярные пентесты, минимальные привилегии у контейнеров.

---

### Риск 5. Интеграция не работает с конкретной 1С заказчика

**Тип:** внешний
**Описание:** у заказчика специфичная, кастомизированная версия 1С. Коннектор не встаёт без доработок, сроки внедрения срываются.
**Уровень:** средний (вероятность средняя, влияние среднее)
**Стратегия — снижение:** перед пилотом проводим технический аудит 1С. Коннектор проектируем модульно: общее API-ядро + адаптеры под версии 1С.

---

### Риск 6. Уход NLP Engineer

**Тип:** внутренний
**Описание:** NLP-инженер — единственный носитель экспертизы по модели. Его уход остановит дообучение и улучшение точности.
**Уровень:** средний (вероятность средняя, влияние среднее)
**Стратегия — снижение:** документация пайплайна инференса и fine-tuning. Эталонные датасеты хранятся в MinIO, доступны команде. Парное программирование с Backend Senior.
