## 2. MVP и MLP

### MVP (минимально жизнеспособный продукт)

**Скелет системы.** Достаточно для запуска пилотного проекта у одного заказчика. Цель: показать, что ИИ корректно классифицирует и маршрутизирует документы внутри 1С.

- **US-11:** Развертывание в закрытом контуре заказчика
- **US-12:** Подключение коннектора к 1С
- **US-1:** Список новых заявок, назначенных ИИ, внутри 1С
- **US-2:** Просмотр оригинала и предзаполненной карточки
- **US-3:** Подтверждение и отправка документа дальше
- **US-4:** Исправление ошибки ИИ в поле (критично для цикла обучения)

### MLP (продукт с минимальной привлекательностью)

То, что превращает «работающий инструмент» в продукт, который хочется купить. Добавляет управленческий контроль и «вау-эффект».

- **US-5:** Индикатор уверенности ИИ по каждому полю
- **US-6:** Ручное переназначение заявки
- **US-7:** Дашборд руководителя: поток, метрики, просрочки
- **US-8:** График загрузки сотрудников и поиск узких мест
- **US-13:** Управление ролями и доступом
- **US-10:** Экспорт отчета для руководителя

## 3. Детализация требований

Выбраны 2 главные истории из MVP:

- **US-11 — Развертывание в закрытом контуре**
- **US-2 — Просмотр оригинала и предзаполненной карточки**

---

### US-11 — Развертывание ИИ-ядра в закрытом контуре заказчика

#### Функциональные требования (ФТ)

| ID | Требование |
|----|------------|
| F-11.1 | Система поставляется в виде Docker-образа (OCI), который может быть загружен на сервер заказчика без доступа в интернет (air-gapped environment). |
| F-11.2 | Установка должна запускаться единым скриптом `install.sh`, который проверяет наличие Docker Engine и необходимых ресурсов (CPU/RAM/Disk), а затем разворачивает все микросервисы. |
| F-11.3 | Конфигурационный файл `.env` позволяет задать параметры подключения к внутренней ERP (1С: Документооборот) и почтовому серверу без пересборки образа. |
| F-11.4 | После запуска система должна быть доступна по внутреннему URL (`https://cogniflow.local/`) и отвечать на `GET /health` статусом 200. |
| F-11.5 | В случае сбоя развертывания, скрипт выводит лог ошибок на экран без зависания, с указанием конкретного шага, на котором произошел сбой. |
| F-11.6 | Администратор должен иметь возможность обновить ИИ-модель, загрузив новый файл модели (`.onnx` или `.pt`) через админ-панель, без полной переустановки. |

#### Нефункциональные требования (НФТ)

| ID | Требование |
|----|------------|
| NF-11.1 | **Производительность:** Время развертывания на чистом сервере (4 Core, 16 Gb RAM) не должно превышать 15 минут. |
| NF-11.2 | **Безопасность:** Все пароли и ключи API в конфигурационных файлах должны храниться в зашифрованном виде (AES-256). Логи не должны содержать чувствительных данных. |
| NF-11.3 | **Надежность:** Система должна сохранять работоспособность при отключении интернета (полный air-gap). |
| NF-11.4 | **Масштабируемость:** Архитектура Docker Compose должна поддерживать горизонтальное масштабирование NLP-воркеров (параметр `WORKERS_COUNT` в `.env`). |
| NF-11.5 | **Совместимость:** Ядро должно стабильно работать на ОС: Ubuntu Server 20.04+, Astra Linux 1.7, РЕД ОС 7.3. |

### US-2 — Просмотр оригинала письма и предзаполненной карточки документа

#### Функциональные требования (ФТ)

| ID | Требование |
|----|------------|
| F-2.1 | При открытии заявки в интерфейсе 1С, форма разделяется на две панели: слева — предпросмотр оригинального письма/PDF, справа — карточка создаваемого документа (Счет, Договор, Акт, Заявка). |
| F-2.2 | В левой панели вложения должны рендериться нативно (PDF, JPG, PNG) без необходимости скачивать файл на диск. |
| F-2.3 | Поля в правой панели, которые ИИ извлек из текста, должны быть **предзаполнены** и подсвечены (например, легкий желтый фон), чтобы пользователь видел, что данные внесены автоматически. |
| F-2.4 | При клике на предзаполненное поле, система должна **подсветить область текста в оригинале письма/PDF**, из которой был взят этот реквизит. |
| F-2.5 | Если ИИ не смог извлечь значение (низкая уверенность), поле остается пустым и помечается красной обводкой для обязательного ручного заполнения. |
| F-2.6 | Загрузка интерфейса не должна блокировать работу пользователя с другими вкладками 1С. |

#### Нефункциональные требования (НФТ)

| ID | Требование |
|----|------------|
| NF-2.1 | **Время отклика:** Время открытия формы заявки (загрузка письма + выполнение NLP-инференса + рендеринг) не должно превышать 2 секунды (95-й перцентиль). |
| NF-2.2 | **Юзабилити:** Интерфейс должен соответствовать гайдлайнам целевой ERP (1С: Предприятие 8), чтобы у пользователя создавалось ощущение нативной функции, а не стороннего плагина. |
| NF-2.3 | **Надежность:** При ошибке загрузки вложения, правая панель все равно должна отобразить все текстовые метаданные, которые удалось извлечь из тела письма. Система показывает плейсхолдер «Ошибка загрузки файла» вместо левой панели. |
| NF-2.4 | **Безопасность:** Предпросмотр документа осуществляется на стороне клиента (рендеринг в браузерном компоненте 1С), файл не передается на внешние серверы конвертации. |
| NF-2.5 | **Доступность:** Интерфейс должен корректно масштабироваться на экранах с разрешением от 1366x768 (старые офисные мониторы) без горизонтальной полосы прокрутки. |
